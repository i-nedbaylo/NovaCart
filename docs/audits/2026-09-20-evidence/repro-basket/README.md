# Диагностика повторного оформления корзины

Программа вызывает настоящий `CheckoutBasketHandler` из проекта через `ProjectReference`. Репозиторий корзины и `IPublishEndpoint` заменены NSubstitute 5.3.0. Производственный код не изменяется.

Два обработчика оформляют одну корзину. Управляемый барьер разрешает им продолжить работу только после получения двух независимых снимков корзины. Это детерминированно моделирует допустимое конкурентное выполнение: оба запроса прочитали корзину до первой публикации и удаления. Затем программа проверяет, что оба обработчика вернули успех и опубликовали два события с разными `Id`, но одинаковыми покупателем, товаром и количеством.

Запуск из корня репозитория:

```powershell
dotnet run --project docs/audits/2026-09-20-evidence/repro-basket/ReproBasket.csproj
```

Код завершения `0` означает **воспроизведение дефекта**, а не корректность checkout. Код `1` означает, что ожидаемый результат не получен; `2` — ошибку диагностического запуска. Если барьер не будет пройден, ожидание ограничено 10 секундами.

Проверка доказывает поведение обработчика при контролируемом чередовании операций. Она не запускает Redis, RabbitMQ, Ordering или Payment и не доказывает создание двух заказов либо банковских списаний на настоящей инфраструктуре. Для полного подтверждения нужен отдельный интеграционный сценарий.
