# Воспроизведение замечаний аудита Ordering/Payment

Консольный доказательный артефакт аудита от 20.09.2026. Не входит в solution и не изменяет продуктовые файлы.

Из корня репозитория:

```powershell
dotnet run --project docs/audits/2026-09-20-evidence/repro-order/Repro.Order.csproj --configuration Release
```

Проверяются настоящие `CreateOrderHandler`, `OrderCreatedIntegrationEventConsumer`, `CancelOrderHandler` и доменные классы. Репозитории, источник данных Catalog, UnitOfWork, сборщик событий и контекст транспорта заменены NSubstitute 5.3.0, уже используемым тестами проекта. PostgreSQL, Redis, RabbitMQ, HTTP и реальные списания не используются.

Ожидаются три строки `ВОСПРОИЗВЕДЕНО`:

1. Товар `100 EUR` превращается в `OrderCreated`/Payment на `100 USD`.
2. Создание заказа на `0` завершается успешно, но Payment consumer выбрасывает исключение без записи и события результата оплаты.
3. `CancelOrderHandler` принимает переход `Paid -> Cancelled`; существующая запись оплаты остаётся `Succeeded`.

Код завершения `0` означает, что все три замечания воспроизведены, а не что бизнес-поведение корректно. После исправления продуктового кода соответствующая проверка должна перестать подтверждать старое поведение.

Границы доказательств: артефакт проверяет вызовы обработчиков и состояние объектов. Он не доказывает результат транзакций в реальной БД, HTTP-коды, доставку событий, конкурентные обновления или отсутствие внешнего возврата. Отсутствие цепочки компенсации отдельно установлено статическим чтением исходников.

Фактически запущено 20.09.2026 в конфигурации Debug с `-p:NuGetAudit=false`; все три сценария воспроизведены, код завершения 0. Результат сохранён в `../repro-order.log`. Отключение проверки NuGet здесь относится только к диагностическому запуску: отдельный свежий аудит всех 43 проектов выполнен и сохранён рядом в `../vulnerable-packages-nuget.json`.
