# Исправления аудита NovaCart — 20 сентября 2026

Статус: изменения исходников и автоматические проверки локального проекта. Это не развёртывание и не приёмка реальных банковских операций. Исходный аудит сохранён отдельно; его номера A01–A14 используются ниже.

## Зависимости

Согласованно обновлены Aspire AppHost SDK/Hosting/Testing до 13.5.4, ASP.NET OpenAPI до 10.0.12 и Microsoft.OpenApi до 2.12.0, System.Security.Cryptography.Xml до 10.0.12, SSH.NET до 2026.0.0. Корневой NuGet.Config задаёт публичный источник проекта, исключая зависимость восстановления от частных источников компьютера разработчика. CI рассматривает NU1901–NU1904 как ошибки.

Полный запуск дополнительно выявил остановку Basket/Ordering/Payment: исходный MassTransit 9.0.1 требовал отсутствующий лицензионный ключ. Для учебного проекта закреплены [MassTransit 8.5.8](https://www.nuget.org/packages/MassTransit/8.5.8) и [MassTransit.RabbitMQ 8.5.8](https://www.nuget.org/packages/MassTransit.RabbitMQ/8.5.8), опубликованные с Apache-2.0. Проверка лицензии не отключалась, покупка или регистрация не выполнялась.

AppHost явно задаёт HTTP-адреса и проверки /health; игнорируемые Git локальные launchSettings.json больше не являются условием запуска сервисов. Сохранены прежние теги контейнеров PostgreSQL 17.4, RabbitMQ 4.1, Redis 7.4: обновление Aspire не должно неявно менять версии хранилищ. В E2E задана успешная симулируемая оплата для обязательной проверки последующего возврата.

В Windows контроллер DCP не принял ранее установленный сертификат localhost. E2E использует штатный временный сертификат DCP через ASPIRE_DCP_USE_DEVELOPER_CERTIFICATE=false; TLS и проверка сертификата через kubeconfig сохраняются. Поведение подтверждено [исходниками Aspire 13.5.4](https://raw.githubusercontent.com/microsoft/aspire/v13.5.4/src/Aspire.Hosting/Dcp/DcpHost.cs). Хранилище доверенных сертификатов пользователя не изменялось.

## Условия обновления существующего стенда

1. Сначала сохранить резервные копии и проверить существующие очереди. Новый контракт BasketCheckout имеет PricingVersion=1. Старые сообщения без серверной котировки намеренно не подтверждаются молча: они перейдут в error queue. Нужно завершить старые оформления старой версией либо отдельно сверить и восстановить их; нельзя придумывать старую цену из текущего Catalog.
2. Обновить Basket, Ordering, Payment и Web согласованно; применить миграцию AddOrderCurrencyAndConcurrency. Для исторических заказов без сохранённой валюты миграция использует прежний USD. Исторически неверную валюту автоматически восстановить невозможно.
3. Существующие корзины без Revision нужно пересохранить через Update Cart перед оформлением. Новый checkout требует BasketRevision из прочитанной корзины.
4. Redis теперь содержит надёжно принятые оформления, а не только удаляемый кэш. Требуются отдельный сохраняемый том, AOF, appendfsync always, noeviction, резервное копирование и мониторинг свободного места. AppHost задаёт эти параметры. Реализация рассчитана на одиночный Redis, не Redis Cluster. Квитанции не имеют TTL: произвольно поздний повтор не должен создать второй заказ; политика архивирования требует отдельного проектирования.
5. В каждой БД Ordering/Payment проверить старые outbox-записи с processed_at IS NOT NULL AND error IS NOT NULL. Новая логика не переоткрывает их автоматически. После проверки причины и актуальности вернуть выбранные ID в pending, сохранив ID и payload. Шаблон ниже. Изменение рабочих БД в этой задаче не выполнялось.
6. Хранилище токенов BFF рассчитано на один экземпляр Web. Для нескольких экземпляров или сохранения сессии после рестарта нужен распределённый store с общей синхронизацией; при потере актуального refresh token может понадобиться повторный вход.
7. Payment по-прежнему симулятор. Перед реальными платежами необходим подтверждённый идемпотентный void/refund у провайдера. Прямой POST /orders не является идемпотентным бизнес-API; его автоматические повторы отключены. Основной checkout корзины идемпотентен по Revision.

### Восстановление старых ошибочных outbox-записей

Выполнять отдельно в нужной БД после разбора сообщений и остановки старого обработчика. Шаблон ничего не изменяет без замены пустого списка выбранных ID и завершения транзакции COMMIT.

```sql
BEGIN;
SELECT id, event_type, created_at, retry_count, error
FROM outbox_messages
WHERE processed_at IS NOT NULL AND error IS NOT NULL
ORDER BY created_at;

UPDATE outbox_messages
SET processed_at = NULL, retry_count = 0
WHERE id = ANY (ARRAY[]::uuid[])
  AND processed_at IS NOT NULL AND error IS NOT NULL;
-- Проверить выбранные строки, затем явно COMMIT вместо ROLLBACK.
ROLLBACK;
```
